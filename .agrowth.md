### Phase 2: Server-Side Data Table (this session)

**Problem:** Route `validateSearch` returned `Record<string, unknown>`, so all search params were typed as `unknown` — causing 8 type errors in pipeline-dashboard and preventing clean compilation.

**Fix:**

1. **`routes/g1/index.tsx`** — Defined and exported `DashboardSearch` interface with typed optional fields (`page?: number`, `sort_by?: string`, etc.) and a `validateSearch` function that coerces URL strings to proper types

2. **`pipeline-dashboard.tsx`** — 
   - Imported `DashboardSearch` type; typed `search` as `DashboardSearch`
   - Imported `G1Application` type; cast `createApplication` body as `G1Application` (fixes gender `string` → `Gender` issue)
   - Fixed `error?.message` → `(error as { message?: string })?.message`
   - All sorting/pagination/column-filters state types now infer correctly from properly-typed search params

**Data Flow (server-side):**
```
User action → TanStack Table callback → navigate with URL params → 
Route.useSearch() returns typed DashboardSearch → queryOptions updates → 
React Query refetches from GET /api/g1-applications?page=...&sort_by=...&full_name=... →
Rust handler parses params, queries DB, returns paginated results →
Table renders with manualSorting/manualPagination/manualFiltering
```

**Bug fix — column Hide not working:** Root cause was TanStack Table's `getHeaderGroups()` returning headers for ALL columns including hidden ones, using `colSpan={0}` to indicate hidden. Browsers don't support `colspan="0"` (defaults to `colspan="1"`), so the `<th>` stayed in DOM. Fixed in `data-table.tsx` by filtering with `header.column.getIsVisible()`.
